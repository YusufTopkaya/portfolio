## Project Notes

- **Design**: the site is retro-only (NES/CRT style) — `light`/`dark`/`system` themes via next-themes only switch the retro palette in `app/globals.css` (`:root` = paper beige, `.dark` = CRT navy). The old glassmorphism design was removed; `.glass*` class names are kept as a legacy API but render as solid pixel panels. Pixel font: Press Start 2P (`--font-press-start` in `app/layout.tsx`). Do NOT import nes.css globally, it clashes with Tailwind preflight.
- **CRT boot effect**: `components/retro/RetroBootEffect.tsx` toggles `html.crt-boot` once on page load; the animation lives at the end of `app/globals.css` and runs on `body` (dot → line → expand → glitch shake).
- **Retro stock ticker**: `components/retro/RetroStockComputer.tsx` (mounted in `components/shared/ClientProviders.tsx`) — desktop: floating CRT PC bottom-left with a working monitor power button (mini CRT on/off animation in `app/globals.css`); mobile (<md): slim ticker bar pinned to the bottom edge. Fetches `/api/stocks` (`app/api/stocks/route.ts`, Yahoo Finance v8 chart API, server-side 15-min revalidate; route response is `Cache-Control: no-store` and the client fetches with `cache: "no-store"` so quotes stay ≤15 min stale). Symbols rotate every 1.5s.
- **Retro micro-components** (all hand-rolled, no retro-react/nes.css dependency): `components/retro/TypewriterText.tsx` (hero name typing, inherits h1 styles), `components/retro/GlitchImage.tsx` (profile photo hover — slice-based "magnet near CRT" wave with chromatic aberration).
- **Personal content**: only `content/en/` and `content/tr/` carry real personal data; other locales are template placeholders. `LICENSE`, `package.json#name`, `public/manifest.json`, `public/.well-known/ai.*` are personalized — keep them on future upstream merges.
- **Twingo Racer cockpit view**: `V` key / CAM touch button toggles between chase cam and a first-person dash overlay (`public/images/twingo-cockpit.png` + 3-frame `twingo-cockpit-wheel.png`, both generated by `scripts/build-cockpit.mjs` from a source JPG — glass keyed to alpha, wheel geometry fractions printed at the end). On touch devices the CAM button lives in the top bar next to mute/pause (`.racer-cam-touch`), NOT between the bottom pedals — it used to cover the car there. In cockpit the car audio is muffled (`setInterior(true)` in `racer/audio.ts`: lowpass cutoff drops, engine/tire levels fall, the low-end rumble survives — cabin acoustics). If the PNGs are missing the toggle hides itself and the game runs chase-only.
- **Twingo Racer tilt steering**: mobile-only option (4th row in the SETTINGS panel, coarse pointers only, persisted in `localStorage("twingo:tilt")`). The phone becomes the wheel: `deviceorientation` gamma (portrait) / beta (landscape, sign flipped on the 270° side) with a 5° deadzone, 30° = full lock, first sample after enabling is the neutral pose, output smoothed (lerp 0.25) into an analog `RacerInput.steer` (-1..1) that overrides the digital left/right flags in the engine. iOS 13+ `DeviceOrientationEvent.requestPermission()` is called inside the toggle click (per-gesture requirement). While tilt is ON the ◀ ▶ steering pads hide; gas/brake pads stay. NOTE: the landscape axis/sign mapping is theoretical (MDN convention) — verify on a real phone and flip the beta sign if steering feels inverted.
- Custom features kept from upstream deletions: `lib/content-protection.ts`, `components/shared/ContentProtection.tsx`, `components/KeySequenceListener.tsx`.
- **Twingo Racer title screen**: the game overlay now opens on a retro key-art title screen before the engine boots — `public/images/twingo-title-mobile.webp` (portrait, 941×1672) and `twingo-title-desktop.webp` (landscape, 1639×960), picked via `<picture>` + `(min-aspect-ratio: 1/1)`. The painted START / LEADERBOARD buttons are transparent %-positioned hit areas in an aspect-locked box (`.racer-title-art` in `app/globals.css`) — if the artwork is ever regenerated, those coordinates must be re-measured. Keyboard: ↑/↓ arms a button, Enter/Space activates, ESC closes. LEADERBOARD opens a read-only top-10 panel (plain `GET /api/highscore`, no token). The engine + submit-token issuance are gated on leaving the title screen, so idling there is free.
- **Twingo Racer audio**: `components/retro/racer/audio.ts` synthesizes everything with raw Web Audio (no assets). The engine voice is a Mk1 D7F firing model — 1149 cc inline-4 four-stroke, f = RPM/30 (28 Hz idle → 200 Hz redline; sub sine + main saw + dominant 2nd harmonic + phase-locked sub-octave saw through a resonant lowpass into a throttle-load-driven waveshaper for growl, plus filtered-noise rumble); lifting off at revs fires bandpassed overrun-crackle pops, and at the gear top with the throttle pinned a rev limiter stutters the ignition in an irregular cut pattern; `EngineState.rpm01` is wheel-speed over the gear's top, so upshifts drop revs by the ratio gap and downshifts kick them up on their own — the 0.28 s shift cut (`GEAR_TOPS`/`SHIFT_TIME` in `engine.ts`, committed gear + aero-only coast during the cut) only ducks load and fires a clutch thump. Acceleration follows the real D7F (0-100 in ~13.4 s, ~20 s more to 150), with an arcade tail to the 180 speedo ceiling. Bandpass-noise brake screech and tire skid (`EngineState.skid`/`braking`), and a synthwave loop that adds layers by score (lead ≥25k, octave doubler ≥60k, double-time hats ≥100k). Three buses (music/engine/menu) sit under the master mute; a SETTINGS panel (title-screen chip + pause-menu option, `.racer-settings` in `globals.css`) sets each 0-10, persisted in `localStorage("twingo:vol")`. The car is silent while paused (`setPaused`, music keeps playing) and after game over; a hidden tab / locked phone suspends the WHOLE AudioContext (`setHidden` wired to `visibilitychange` in `TwingoRacer.tsx`, alongside the existing auto-pause + key-drop) so nothing plays while the game isn't visible — resume is seamless (the music scheduler's lookahead just waits out the freeze). Braking also lights the car sprite's stop lamps (chase view, drawn after the sprite in `engine.ts` render). Boost adds its own voice on the engine bus: a swept-bandpass NOS whoosh + a sub-bass punch (130→45 Hz sine drop) on activation, then a detuned sawtooth growl (65→195 Hz through a rev-following lowpass) + lowpassed air roar under a faint whistle while `boostT` burns (the roar is the audible countdown), and a blow-off "psshh" (3400→1300 Hz) on the falling edge — `drive()` takes a `boost` flag from `TwingoRacer`; pause/game-over/stop all zero the boost gain. Dev only: `window.__twingo` exposes the engine for e2e probes.
- **Twingo Racer distance difficulty**: every 2 km (`LEVEL_EVERY_KM`) bumps `state.level` in `components/retro/racer/engine.ts` (uncapped) and shows a brief 2.2 s `LEVEL X` canvas flash with the level's fuel-consumption multiplier underneath (`FUEL xN.NN` in the same face, accent orange — same font and size, no backing band). Difficulty applies through pure multipliers on the generated track data (never mutated): `curveGain` (+8%/level, cap 1.6) sharpens every bend and `hillGain` (+7%/level, cap 1.5) steepens hills — both must be applied at EVERY `.curve` / `world.y` read site (projection, mirror, background parallax) or the world tears. Hill sections are grade-capped in `track.ts` (`MAX_GRADE = 0.35` on the stored cosine-eased peak — sections STRETCH to keep amplitude, never flatten): past ~0.8 a descent compresses into a marking-less sliver at the screen edge, past ~1.2 the far side fails the backface test wholesale and the road vanishes behind the crest (the "yol boşalıyor" bug), and `hillGain` multiplies on top — 0.35 stored keeps the effective grade ≤ ~0.5 at max gain, worst-case road band ~28% of the screen. ONE exception: the physics centrifugal push uses the softer `curveGrip` (+4%/level, cap 1.3) instead, and its displacement is capped at ±1.6× (the scrub speed-bleed still uses the raw force) — so a blown corner drifts the car out over ~a second (catchable with counter-steer) instead of an instant eject, and `FAR_OFFROAD` is 2.5 (a grass run-off window before the respawn teleport). Gas cans don't get scarcer with level but drift toward the road edges (`canSpread`, cap 1.35×). Fuel is the death clock, OutRun-style: the drain is nearly flat per second (`0.09 + 0.04·p²` dots/s) so fuel-per-km falls monotonically with speed — flat out is always the most economical pace, crawling at 60 km/h dies in ~3 km. `drainGain` (+5%/level, cap 1.4) plus score-based scarcity (1% of cans hidden per 4000 points, cap 50%, golden-ratio order over the can ordinal, big cans resist at half rate) close the gap in the deep levels — kept soft so a clean can chain survives well past level 5 and a missed can is a setback, not a death sentence. Two relief valves: below 2 dots with nothing collectible in the next ~90 segments, a one-shot **mercy can** (`ordinal: -1`, scarcity-immune) materialises on the car's line ~60 segments out, re-armed once the tank reaches 2.5; and a can grabbed with a near-full tank doesn't waste its overflow — each wasted dot becomes 2 s of **BOOST** (0.5 s floor so even a 7.01-dot top-up pays out, cap 10 s, top speed ×1.12 to ~202 km/h (ceiling eases in AND out — the extra speed bleeds back to 180 over ~1 s of aero drag when the boost ends, never snaps), accel ×1.3, blinking BOOST readout with the seconds left — above the gauge on desktop, big and centred at the top on portrait phones — and BOOST burns the overflow only, the tank drain freezes while boostT>0 — and for 0.3 s after ANY can grab, so a fresh tank never feels instantly eaten). **Fuel-chain streak**: consecutive cans without a miss count in `state.streak` (an ACTIVE can driven past resets it — scarcity-hidden cans are skipped, not broken; a respawn resets it too), and the ladder REPEATS every 10 cans — 3/5/10 → 13/15/20 → 23/25/30… pay +1.5/+3/+5 s of BOOST (`streakReward`, same boostT pool). A full clean lap pays 9.5 s vs the 8 s from deliberately breaking a chain after 10 and re-farming 3/5, so staying clean always wins — no incentive to drop a combo on purpose), with a red pixel jerrycan stamped "GAS" + `xN` counter (visible from x1, doubled in size on portrait viewports — the buffer keeps its desktop design size so the physical pixels are tiny) in the corner opposite the LCD cluster — a flame tracks the lap (1→2→3→4 tongues through 3/5/10, resets each lap) so the fire itself shows how close the next +5 s is, and a broken chain burns the can out in a ~0.9 s flare — and a rising arpeggio in `audio.ts` (the 10-can eşik popup'ı `COMBO N! +5s` yazar — tamamlanan döngü prestijidir, ara ödüller `STREAK n!` kalır). While BOOST is active the fuel gauge's lit dots frost over ice-blue (`frozen` flag threaded through `drawFuelGauge`/`renderCluster`/`renderDashCluster`) so the frozen drain reads at a glance. An overflow pickup's rising popup says OVERFLOW (not BOOST) so the driver knows where the boost seconds came from.. A stranded respawn costs −1 dot; at empty the engine dies but the car coasts, and a can grabbed while coasting revives it (coast-over-checkpoint mercy).
- **Twingo Racer track & sky**: the endless track generates into a fixed 2048-slot ring (`components/retro/racer/track.ts` — ~10 s buffered ahead via `AHEAD_SEGMENTS` 600, old slots overwritten, no splice; the engine reads slots as `absIndex % capacity` via `firstIndex()`/`generated()` from the generator). The capacity margin is load-bearing: `extend()` fills WHOLE sections and can overshoot its target by up to one grade-capped rolling-hills run (~540 segments), so the ring must stay ≥ that + the render window ahead of the car — if `firstIndex()` ever passes the car, `findSegment` clamps to a segment AHEAD of the camera and the world renders from a wrong offset (compressed road line, mass backface culls, fake near-fill, then a snap when the car catches up — the "road teleport" glitch). 2048 vs ahead 600 + overshoot ~540 leaves ~900 of cushion. The layout seed is the UTC day number (`Date.now()/86400000` in `TwingoRacer.tsx`), so everyone races the same track on the same day and same-day highscores are comparable. Gas-can pickup scans every segment crossed in a frame (full speed + a slow frame spans 2+ segments — single-segment checks tunnelled through cans). The sky is a day/night cycle (`DAY_LENGTH` 300 s in `engine.ts`): procedural gradient lerped through day → sunset (the classic palette) → night keyframes, arcing pixel sun and crescent moon, hash-placed twinkling stars, and a full-frame ambient overlay (night dims to navy, sunset warms orange) applied BEFORE the HUD cluster so the LCD glows in the dark. Clouds/mountains stay prebuilt canvases. The canvas is never cleared — every region must be repainted each frame or stale pixels survive; the sky's top parallax strip (`|skyShiftY|`, BOTH signs — downhill slides the gradient off-screen, uphill starts it lower) is painted with the top gradient colour, otherwise the strip keeps the night's dark band into the daytime. **Near gap-fill**: on steep descents (worst at high `hillGain`) every segment closer than the valley floor fails the `p2.y >= p1.y` visibility test, so the nearest painted road line can hang above the buffer's bottom edge for 1-5 frames — an unpainted strip there keeps stale pixels (ghost car parts, old pickup sparkle). The render captures the first painted line (`nearLine`) and continues its grass + extrapolates its road edges down to the bottom edge — the descent mirror of the crest gap-fill. Jake Gordon never needed this because his hills are gentle enough that the nearest line always projects below the viewport. Dev only: `createEngine({ debug })` (set by `TwingoRacer` outside production, same gate as `window.__twingo`) collects per-render road diagnostics into `engine.probe` (near-fill gap, cull counts, segment projection samples) for e2e bug hunts.
- **Twingo Racer highscores**: `/api/highscore` (`app/api/highscore/route.ts` + `lib/highscore.ts`) stores scores in `data/highscores.json` (override with `HIGHSCORE_FILE`). Retention: all-time top-50 plus everything from the last 40 days (hard cap 300) so the period boards have history. `GET ?period=all|monthly|weekly|daily` returns the top-10 over rolling 30d/7d/24h windows — the game shows these as ALL/30D/7D/24H tabs on the title and game-over leaderboards (selection persisted in `localStorage("twingo:board-period")`; after a submit the tab pins to ALL because the returned rank is all-time). The store file carries a `version` field — a version mismatch wipes scores but keeps nonces (bumped to 2 when the scoring model changed; the manual alternative is deleting the file in the Dokploy volume). Submissions need a single-use HMAC token signed with `HIGHSCORE_SALT` (server-only env, never `NEXT_PUBLIC_*`) plus score/duration plausibility; initials are filtered by `lib/profanity.ts`. A valid token IS the anti-spam proof: the per-IP submit rate limit only counts FAILED attempts (a first-time submitter behind a shared IP no longer eats a 429); GET has its own generous 600/15 min bucket. Without `HIGHSCORE_SALT` the API answers 503 and the game hides the leaderboard. Submit rejections and successful saves are logged to the server console with client IP, status, reason, and payload. Docker: `/app/data` is chowned to `nextjs` — mount a volume there in Dokploy or scores reset on redeploy. The privacy page has a matching `privacy.leaderboard` section in all 13 locales.
