# Twingo Racer — Input (cockpit, tilt, gamepad)

- **Twingo Racer cockpit view**: `V` key / CAM touch button toggles between chase cam and a first-person dash overlay (`public/images/twingo-cockpit.png` + 3-frame `twingo-cockpit-wheel.png`, both generated by `scripts/build-cockpit.mjs` from a source JPG — glass keyed to alpha, wheel geometry fractions printed at the end). On touch devices the CAM button lives in the top bar next to mute/pause (`.racer-cam-touch`), NOT between the bottom pedals — it used to cover the car there. In cockpit the car audio is muffled (`setInterior(true)` in `racer/audio.ts`: lowpass cutoff drops, engine/tire levels fall, the low-end rumble survives — cabin acoustics). If the PNGs are missing the toggle hides itself and the game runs chase-only.
- **Twingo Racer tilt steering**: mobile-only option (4th row in the SETTINGS panel, coarse pointers only, persisted in `localStorage("twingo:tilt")`). The phone becomes the wheel: `deviceorientation` gamma (portrait) / beta (landscape, sign flipped on the 270° side) with a 5° deadzone, 30° = full lock, first sample after enabling is the neutral pose, output smoothed (lerp 0.25) into an analog `RacerInput.steer` (-1..1) that overrides the digital left/right flags in the engine. iOS 13+ `DeviceOrientationEvent.requestPermission()` is called inside the toggle click (per-gesture requirement). While tilt is ON the ◀ ▶ steering pads hide; gas/brake pads stay. NOTE: the landscape axis/sign mapping is theoretical (MDN convention) — verify on a real phone and flip the beta sign if steering feels inverted.
- **Twingo Racer gamepad**: Xbox / PlayStation / no-name pads via the Gamepad API standard mapping (`components/retro/racer/gamepad.ts` — browsers remap known controllers to the standard layout, so fixed indices cover all: left stick X analog steer (0.15 deadzone) / d-pad digital, RT gas, LT brake, A confirm, B + Start = Escape, Y = camera (V), Select = restart (R), d-pad ↑↓←→ + stick X/Y edge-step the menus, LB/RB cycle the leaderboard period tabs via a `twingo:board-step` CustomEvent (only while a board is visible — never mid-run)). The triggers are ANALOG with a 0.08 deadzone in `pollPad()` (resting-trigger noise below that reads as zero — without it a jittery resting LT latches the brake lamps on): `pollPad()` returns `gasAmt`/`brakeAmt` 0..1 (digital triggers report 0/1), merged into `RacerInput.gasAmt`/`brakeAmt` (keyboard falls back to 0/1 through the boolean flags) — the engine scales accel/braking by the pull (a feathered RT is a feathered throttle). Poller focus-gate'lidir: Gamepad API focus-scoped DEĞİL — site görünür ama unfocused'ken (ikinci monitörde başka oyun pad'le oynanırken) pad state'i akmaya devam eder ve %5-6'lık bir trigger arabadan hayalet sürücü yaratırdı; `document.hasFocus()` yoksa `padInputRef` null + synthetic key dispatch yok. (A feathered RT holds a cruise below the ceiling) and arms the stop lamps / brake audio past 0.12 of travel so a noisy resting LT never glows. Non-standard pads that leave buttons 12-15 unmapped get d-pad fallbacks: the Firefox hat axis (`axes[9]` eighth-step encoding, neutral when >1.1 or |hat|<0.05) then ±0.5 on `axes[6]`/`axes[7]`. One rAF poller in `TwingoRacer.tsx` (the title screen has no engine loop) writes continuous state to `padInputRef` — merged into the engine input each frame (pad stick > tilt > keyboard for steer; pedals merge as `max(keyboard, trigger pull)`) — and turns edge presses into SYNTHETIC KeyboardEvents on window, so every existing menu handler works untouched. On the game-over initials form a connected pad swaps the text input for the classic arcade initials spinner (`.racer-spinner`, `SPIN_CHARS` A-Z0-9): d-pad/stick ↑↓ cycles the armed slot's letter (380 ms then 110 ms auto-repeat on hold), ←→ moves slots, A locks and advances (from the 3rd slot it submits), B steps back, Start submits — it drives the same `initials` state via a `twingo:spin` CustomEvent, so the submit path is untouched. CRITICAL: `qualifies` (and so `spinnerOn`/`goFormPendingRef`) is gated on `gameOver` — without that, a fresh token + a STALE finalScore (it survives run resets, now zeroed in the token effect) + a small board turned the spinner on MID-RUN: the pad edges were silently eaten by an invisible spinner (menu beeps while driving) and Start/A submitted the stale score as AAA (the YSF/AAA duplicate). `submitScore` additionally locks re-entry synchronously (`sendingRef` — the submitState closure let same-frame double dispatches through), consumes the token client-side up front (restored on failure so retry works), and discards a resolution that lands in a newer run (`runIdRef` — a late success once hid the next run's form and showed a stale RANK). While actually DRIVING the arrow edges are suppressed — they double as the keyboard drive keys and a synthetic keydown without keyup would latch gas/brake on (only the one-shot actions pause/camera/restart dispatch mid-run). The quick-pause overlay (PAUSED — …) resumes on ANY pad press instead of a click, and ESC on the game-over screen quits to the title (pad B). The game-over action row is pad-navigable once the initials form releases the keys (submitted or not qualifying): ←/→ (d-pad or stick) toggles the armed button between PLAY AGAIN and QUIT (`goSel`, `racer-go-armed` glow, keyboard arrows work too), Enter/A runs it, R/Select stays a PLAY AGAIN shortcut — while the form is pending (`goFormPendingRef` = qualifies && submitState !== "done") arrows/Enter belong to the input/spinner. Pad-aware hint texts swap while a pad is connected (`padConnected`): the desktop legend (`.racer-keys`) shows RT/LT/LS/Y/SEL/START instead of keyboard rows, plus PAUSED — PRESS START, pause menu "A SELECT — B RESUME", settings "D-PAD ROW / ADJUST", game over "◀ ▶ SELECT · A OK · B QUIT". The browser only exposes a pad after its first button press.
